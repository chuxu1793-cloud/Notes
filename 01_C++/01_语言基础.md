# C++ 语言基础

本笔记按"修饰符 → 类型与内存 → 初始化 → 数值表示 → 函数细节"的顺序整理 C++ 语言层面的基础知识点。重点是那些**容易被误记的规则**（const 的结合方向、static 的链接性、inline 的现代含义、有符号右移与溢出的标准行为），以及能直接在代码里复用的结论。凡是标准未规定、只在特定编译器/平台上成立的说法，都在文中标注了适用条件。

## const

### const 修饰指针

```cpp
const char *ptr;        // 指向 const char 的指针：不能通过 ptr 改内容
char const *ptr;        // 与上者完全等价
char * const ptr;       // const 指针：ptr 本身不能改，但可以改它指向的内容
```

`const char *ptr` 只表示"对 ptr 而言这个值是常量"，并不要求它指向的对象真的是 const。下面的代码完全合法：

```cpp
char str[] = "hello";
const char *ptr = str;
str[0] = 'H';           // OK，通过原变量修改
// ptr[0] = 'H';        // 错误，不能通过 ptr 修改
```

判断 const 到底修饰谁，标准规则是：**const 修饰它左边紧邻的类型；若 const 处于声明的最左端，则修饰它右边的类型**（"const 修饰其左边的对象"这个口诀只在 const 不在最左端时成立）。

```cpp
int const * p1;              // const 修饰 int：p1 指向 const int
int * const p2;              // const 修饰 p2：p2 是 const 指针
int * const * p3;            // const 修饰 p3 所指的那个指针
int * const * const p4;      // 第一个 const 修饰 p4 所指的指针，第二个修饰 p4
```

`const char* const p` 则是"指针本身和指向的内容都不可变"。

### 顶层 const、底层 const 与指针类型相容性

`const` 修饰指针本身时叫顶层 const（top-level const），修饰所指对象时叫底层 const（low-level const）。赋值时顶层 const 可以被忽略，底层 const 必须严格相容——这是下面这个经典告警的根源：

```cpp
char s1[] = "hello", s2[] = "world";
char* name[] = {s1, s2};
char **cp = name;
const char **ccp = cp;   // error: char** 与 const char** 是不相容类型
```

原因是 `cp` 指向的类型是 `char*`，`ccp` 指向的类型是 `const char*`，两者是不相容的类型（就像 `int*` 与 `double*` 不相容）。更本质地说，如果可以这样赋值，就能绕过 const 修改真正的 const 对象：

```cpp
const char c = 'x';
const char *pc = &c;
const char **ppc = &pc;   // 假设允许
char *p = nullptr;
*ppc = p;                 // 把 pc 指向了非 const 的 p
*p = 'y';                 // 于是修改了 const 对象 c
```

标准对赋值的要求是：两个操作数都是指向"相容类型"的指针，且**左边指针所指类型必须具有右边指针所指类型的全部限定符**。因此正确的写法是让 const 出现在更外层：

```cpp
char * const * ccp = cp;   // OK：ccp 指向 char* const，与 char* 相容
```

### const 成员函数

1. `const` 写在成员函数参数表之后，表示该函数不会修改对象的可见状态；
2. const 对象只能调用 const 成员函数，非 const 对象两者都能调用；
3. 任何不修改数据成员的函数都应声明为 const——这既是接口契约，也让 const 对象可用；
4. 例外：`mutable` 修饰的成员在 const 成员函数中仍可修改（常用于缓存、互斥量）；
5. const 成员函数中 `this` 的类型是 `const T* const`，因此不能返回指向成员的普通引用，只能返回 const 引用。

最后一点有个经典陷阱：给 `String` 提供 `operator[]` 时，只写非 const 版本，const 对象无法取下标；补上 const 版本但返回值忘了加 const，又会被用来修改 const 对象：

```cpp
char& operator[](int pos)              { return data[pos]; }        // 非 const 对象
const char& operator[](int pos) const  { return data[pos]; }        // const 对象
```

若第二个版本返回 `char&`，则 `const String str = "She"; str[0] = 'T';` 能编译通过并把 str 改成 "The"，const 形同虚设。所以 **const 成员函数返回成员引用时，返回值必须加 const**。

两个版本构成重载（const 参与成员函数的重载决议），编译器按对象的 const 性质选择。注意：`const` 修饰的是对象而不是函数本身，因此不能只靠"函数体内行为不同"来区分。

### const 数组与 sizeof

```cpp
const char *buf[] = {"gdfsfgd", "gdfsgf", "wee"};
int len = sizeof(buf);          // 3 * sizeof(char*)，64 位下为 24，32 位下为 12
int num = len / sizeof(char*);  // 3
```

`const char *buf[]` 是**指针数组**：元素是一个个指针，`sizeof(buf)` 求的是整个数组占用的字节数；但每个元素的 `sizeof` 只得到指针大小，与字符串长度无关。

## static

static 在不同位置含义完全不同，可以按"链接性 / 生存期 / 存储"三条线来记。

### 静态全局变量与静态局部变量

- **静态全局变量**：内部链接（internal linkage），只在本翻译单元（.cpp）可见，其他文件即使写 `extern` 也找不到；
- **静态局部变量**：作用域仍在函数内，但具有静态存储期，程序运行期间只初始化一次，函数退出后值保留；
- 未显式初始化的静态变量（含局部静态）在程序启动时零初始化；
- C++11 起，局部静态变量的初始化是线程安全的（编译器插入一次性初始化保护），这也是"magic static"单例的基础。

### 静态函数

static 修饰函数使函数具有内部链接，只在本文件可见，其他文件无法取到它的地址。工程里两个 .cpp 各自定义同名 `static int add()` 不会冲突，正是这个原因。

头文件里的 static 函数有个坑：在头文件中**声明** static 函数、在某个 .cpp 中**实现**，其他包含了该头文件的 .cpp 只会得到声明而没有函数体，链接时报未定义。反过来，若直接在头文件中定义 static 函数，每个包含它的 .cpp 都会生成一份函数体副本，造成代码膨胀。这也是现代 C++ 用 `inline` 函数放在头文件里替代 static 函数的原因。

若静态函数是**类的静态成员函数**，它属于类而非文件，具有外部链接，可以在其他文件中调用。

### 类的静态数据成员：是"定义"而不是"初始化"

"静态成员变量一定要初始化"这个说法不准确，准确的说法是**静态成员变量必须在类外定义**。类内的写法只是声明，不分配内存；类外的定义才分配内存，是否赋初值是可选的。

```cpp
class A {
public:
    static int a;      // 声明，未分配内存
};

int main() { printf("%d", A::a); }   // 链接错误：对 A::a 未定义的引用
```

```cpp
class A { public: static int a; };
int A::a = 3;          // 定义并初始化
// int A::a;           // 只定义不初始化，同样可以编译
int main() { printf("%d", A::a); }   // 3
```

因为类内只是声明，编译器不需要知道静态成员类型的大小，所以下面这种"前置声明 + 静态成员"的写法可以编译通过：

```cpp
class B;               // 完全不知道 B 的定义

class A {
public:
    static B bb;       // 只是声明，编译器无需为 bb 分配内存
};
```

补充：C++17 起可以用 `inline static int a = 3;` 直接在类内定义，无需类外定义；早期标准下"必须在类外定义"的规则不再是无条件的。

### 静态成员函数

- 可以在类内或类外实现，但必须在类内声明；只在类内声明处写 `static`，类外实现时不写；
- 没有 `this` 指针，因此不能直接访问非静态数据成员、不能调用非静态成员函数，只能访问静态成员；
- 不是任何对象的组成部分，不依赖对象调用，所以**不能声明为 const**（const 限定的是对象）；
- **不能声明为 virtual**：静态函数本质上只是"带访问控制的全局函数"，没有对象、没有虚表入口，谈不上动态绑定；
- 可以用 `类名::函数()` 直接调用，不需要对象。

### 静态成员的继承

- 父类的 static 成员在派生类中依然可用，但受访问控制限制（父类 private 段中的不可访问）；
- 派生类与父类**共用同一份**静态变量存储空间，用静态变量做引用计数时尤其要注意这一点；
- static 函数没有"虚函数"一说，派生类再定义同名 static 函数只是隐藏。

```cpp
class Base {
public:
    static int a;
    static void Fun() { std::cout << "静态成员函数可以被继承!" << std::endl; }
};
int Base::a = 1000;

class Derived : public Base { };

int main() {
    std::cout << Derived::a << std::endl;   // 1000
    Derived::Fun();
}
```

## inline

inline 最初的目的之一是替代表达式形式的宏：编译期把调用点用函数体替换，省掉调用开销，同时保留参数类型检查和作用域规则。它相对宏的优势是：

1. 展开后没有函数调用开销，但会增加目标代码体积；
2. 编译器会像对待普通函数一样检查参数类型，消除了宏的副作用与优先级陷阱；
3. 可以是类的成员函数，因此能访问 protected/private 成员。

使用要点：

1. `inline` 是**实现**用的关键字，应写在定义处或定义之前的声明中；若定义先于 inline 声明出现，则该声明非法；
2. 函数体应当短小；语句过多时编译器通常不会内联；
3. **现代语义**：`inline` 只是给编译器的建议，编译器可以完全忽略（`-O0` 下常被忽略；无法去虚化的虚调用不能内联，递归调用与取地址的调用通常也不会展开）。原文中"函数体内有循环/if/switch 就一定不内联"是早期编译器的经验规则，现在不成立；
4. **链接语义才是 inline 的硬性作用**：inline 函数允许在多个翻译单元中出现相同定义（ODR 例外），由链接器合并成一份，因此可以安全地放在头文件中。原文"一个文件中定义的内联函数不能在另一个文件中使用"只对非 inline 的 `static` 函数成立，对真正的 inline 函数是错误的；
5. 定义必须在调用点可见（通常放在头文件中），否则编译器拿不到函数体，只能退化为普通调用。

## explicit

`explicit` 修饰构造函数，禁止编译器用它做隐式类型转换。默认情况下单参数构造函数是隐式的（implicit），可以把参数类型自动转换为类类型：

```cpp
class CxString {
public:
    char *_pstr;
    int _size;
    CxString(int size) {                 // 隐式，可被用于转换
        _size = size;
        _pstr = (char*)malloc(size + 1);
        memset(_pstr, 0, size + 1);
    }
    CxString(const char *p) {
        int size = strlen(p);
        _pstr = (char*)malloc(size + 1);
        strcpy(_pstr, p);
        _size = strlen(_pstr);
    }
};

CxString s1(24);        // OK
CxString s2 = 10;       // OK：等价于 CxString temp(10); CxString s2 = temp;
CxString s3;            // 错误：没有默认构造函数
CxString s6 = 'c';      // OK，但走的是 CxString(int)，size 等于 'c' 的 ASCII 码
s1 = 2;                 // OK：先隐式构造临时对象，再赋值
```

`s2 = 10`、`s6 = 'c'` 这类写法语义上莫名其妙（`_size` 表示缓冲区大小），加 `explicit` 即可禁止：

```cpp
explicit CxString(int size);
// CxString s2 = 10;    // 错误：explicit 取消了隐式转换
// s1 = 2;              // 错误
CxString s2(10);        // 仍然 OK，显式调用不受影响
```

关于适用范围的准确说法：

- **C++98/03**：explicit 只对单参数构造函数有效，参数个数 ≥ 2 时不会产生隐式转换，写了也没用；
- 例外：除第一个参数外其余参数都有默认值时，只传一个参数仍等效于单参数构造，explicit 依然有效（`explicit CxString(int age, int size = 0);`）；
- **C++11 起**：explicit 可用于任意多参数构造函数，作用是禁止**拷贝列表初始化**（`CxString s = {1, 2};` 非法），直接初始化 `CxString s(1, 2)` 和 `CxString s{1,2}` 仍可用；C++11 起 explicit 还可以修饰转换运算符（`explicit operator bool()`）。

重载决议上的一个细节：explicit 构造函数不参与隐式转换，所以下面的 `a = num` 会退而选择非 explicit 的 `AA(short)`：

```cpp
class AA {
public:
    explicit AA(int a) { std::cout << "int" << std::endl; }
    AA(short a)        { std::cout << "short" << std::endl; }
};

int num = 10;
AA a(num);      // 输出 "int"
AA b = num;     // 输出 "short"：explicit AA(int) 被排除，int 收窄为 short
```

## sizeof

- 返回类型是 `size_t`（无符号整型，具体是 `unsigned long` 还是 `unsigned long long` 取决于平台和 ABI，原文只写 `unsigned long` 不够准确）；
- 是编译期运算符，不进行求值（C99 的变长数组 VLA 除外；C++ 没有 VLA，数组形参已退化为指针，对形参求 `sizeof` 得到的仍是指针大小）；
- 对指针求 `sizeof` 得到的是指针本身的大小（32 位 4 字节，64 位 8 字节），不是它指向的内存大小。

```cpp
int buf1[10];
int *buf2 = new int[10];

sizeof(buf1);   // 40：静态数组是一种数据结构，sizeof 知道总长度
sizeof(buf2);   // 8（64 位）：动态数组只是一个指针
```

因此对数组求元素个数只能用 `sizeof(arr)/sizeof(arr[0])` 这种形式，且仅当 arr 仍然是数组类型（没有退化为指针）时成立。现代写法是 `std::size(arr)` 或 `std::extent`。

## 指针与引用

- **本质**：指针是一个变量，存放的是另一个对象的内存地址；引用是已存在对象的别名，与被引用对象是同一个东西；
- **初始化**：指针可以不初始化或初始化为 `nullptr`；引用定义时必须绑定到对象，之后不能改绑；
- **多级**：指针可以有多级（`int**`），引用只有一级（不存在"引用的引用"，`int&&` 是右值引用，不是引用的引用）；
- **可否为空**：指针可以为空，引用在合法程序中不能为空（但可以通过解引用空指针来构造出"悬空引用"，属于未定义行为）；
- **占用空间**：标准没有规定引用是否占用存储。实现上引用通常用指针实现（占一个指针大小），但在编译期能被完全优化掉时不占空间，所以"引用不占内存"只是常见实现下的观察，不是语言保证。

其余经典差异：指针可以重新赋值指向别的对象，引用不行；`sizeof(引用)` 得到的是被引用对象的大小，`sizeof(指针)` 得到指针大小；对引用取地址得到被引用对象的地址；引用没有顶层 const 的概念（引用本身天然不可改绑）。

## 数组指针与指针数组

名词中间加个"的"就清楚了：**数组的指针**（指向数组的指针）与**指针的数组**（元素为指针的数组）。判断依据是运算符优先级 `()` > `[]` > `*`：

- `(*p)[n]`：先看括号，p 是指针，指向一个长度为 n 的一维数组 → 数组指针；
- `*p[n]`：先看 `[]`，p 是数组，元素是指针，共 n 个 → 指针数组。

中心词就是 p 的类别。

### 数组指针 `(*p)[n]`

```cpp
int a[5] = {1, 2, 3, 4, 5};
int (*p)[5] = &a;     // p 指向整个数组

printf("%p\n", a);      // 首元素地址
printf("%p\n", p);      // 数组的地址（数值与 a 相同）
printf("%p\n", *p);     // *p 就是数组 a 本身，退化为首元素地址
printf("%p\n", p[0]);   // 同上，首元素地址
printf("%d\n", **p);    // 1
printf("%d\n", *p[0]);  // 1
```

数组指针最重要的用途是接收二维数组：

```cpp
int b[3][4];
int (*pp)[4] = b;   // pp = b 与 pp = &b[0] 等价
pp++;               // 前进一行，指向 b[1]
```

所以数组指针也称**行指针**。二维数组名 `int a[2][3]` 的类型是"指向含 3 个 int 的一维数组的指针"，即 `int(*)[3]`；`a + 1` 以行为单位移动。

### 指针数组 `*p[n]`

```cpp
int a = 1, b = 2;
int *p[2];
p[0] = &a;
p[1] = &b;

int *pp[3];
int c[3][4];
for (int i = 0; i < 3; ++i) pp[i] = c[i];   // 每行分别赋值
```

### `&a` 与 `a` 的区别（经典笔试题）

`int a[5];` 中 `&a` 与 `a` 的**数值相等但类型不同**：`&a` 的类型是 `int(*)[5]`（整个数组），`a` 退化后是 `int*`（首元素）。因此加 1 后的偏移量不同：

```cpp
int a[5] = {1, 2, 3, 4, 5};
int *ptr = (int*)(&a + 1);         // 越过整个数组，指向 a[5]
printf("%d,%d", *(a + 1), *(ptr - 1));   // 2,5

int *ptr2 = (int*)(a + 1);         // 只前进一个 int
printf("%d,%d", *(a + 1), *(ptr2 - 1));  // 2,1
```

另一道同类题：`int a[10];` 下列哪个**不能**表示 `a[1]` 的地址？

- A. `a + sizeof(int)` —— 不能。32 位下等价于 `a + 4`，即 `a[4]` 的地址；
- B. `&a[0] + 1` —— 能；
- C. `(int*)&a + 1` —— 能。先把"数组地址"转成 `int*`，再按 int 步长加 1；
- D. `(int*)((char*)&a + sizeof(int))` —— 能。按字节偏移 4 后再转回 `int*`。

注意 C 的 `(int*)&a + 1` 与题目里的 `(int*)(&a + 1)` 完全不同：前者是"先转型再加 1"，后者是"先加 1（跨整个数组）再转型"。

## 内存对齐

### 对齐公式

申请内存时常见的字节数上调写法：

```cpp
nBytes = (nBytes + align - 1) & ~(align - 1);
```

它把 `nBytes` 上调到 `align` 的整数倍（要求 `align` 是 2 的幂）。`~(align-1)` 是低位置 0 的掩码，与操作等价于去掉除以 `align` 的余数，因此等价于 `[(nBytes + align - 1) / align] * align`。用位运算纯粹是为了效率。

### 对齐规则

基本约束："数据项只能存储在地址是数据项大小整数倍的内存位置上"，例如 int（4 字节）只能放在 0、4、8… 这样的偏移上。

结构体对齐分两步：

1. 第一个成员位于偏移 0；其后每个成员的偏移必须是 `min(#pragma pack(n), 该成员自身大小)` 的整数倍，不足则填充；
2. 所有成员各自对齐完成后，结构体本身还要对齐，对齐数为 `min(#pragma pack(n), 最大成员大小)`，结构体总大小必须是该值的整数倍。

`#pragma pack(n)` 用于设置 n 字节对齐，VC6 默认 8，GCC 默认按自然对齐（等价于不限制）。

```cpp
struct A { char a; int b; short c; };   // 1 + pad3 + 4 + 2 + pad2 = 12
struct B { short c; char a; int b; };   // 2 + 1 + pad1 + 4       = 8
```

同样的成员，只改顺序就差了 4 字节——这是"按大小降序排列成员"这一优化建议的来源。（结构体大小还与编译器和 `pack` 设置有关，上例为默认自然对齐下的常见结果。）

### 为什么需要对齐

1. **平台原因**：不是所有硬件平台都能访问任意地址上的任意数据，某些平台在非对齐地址取值会抛硬件异常；
2. **性能原因**：对齐后 CPU 访存次数减少，速度明显提升；跨缓存行/页的访问代价更高。

## 初始化列表与引用成员

### 为什么需要初始化列表

构造函数分两个阶段：**初始化阶段**（成员初始化列表）和**计算阶段**（函数体）。函数体内的语句只能"赋值"，不能"初始化"：

> 从无到有叫初始化（调用拷贝/移动构造函数，创建新对象）；赋值（调用赋值运算符）不创建新对象，而是修改已有对象。

const 对象和引用只能初始化、不能赋值，因此它们唯一的机会就是初始化列表。必须用初始化列表的情况有四类：

1. **成员是 const 类型**；
2. **成员是引用类型**——此时该类不能有默认构造函数，且必须在初始化列表中绑定；
3. **成员是没有默认构造函数的类类型**——创建对象时必须初始化每一个成员，没有默认构造函数就无法在函数体内"补"；
4. **存在继承关系且基类没有默认构造函数**——派生类必须在初始化列表中显式调用基类构造函数。

```cpp
class A {
public:
    A(int &v) : i(v), p(v), j(v) {}     // const 成员 i、引用成员 j 都必须在初始化列表
    void print_val() { std::cout << "hello:" << i << "  " << j << std::endl; }
private:
    const int i;
    int p;
    int &j;
};

int main() {
    int pp = 45;
    A b(pp);
    b.print_val();
}
```

运行输出：

```text
hello:45
```

第 3 类情况：

```cpp
class Base {
public:
    Base(int a) : val(a) {}
private:
    int val;
};

class A {
public:
    A(int v) : p(v), b(v) {}    // b 没有默认构造函数，必须显式初始化
private:
    int p;
    Base b;
};
```

第 4 类情况：

```cpp
class A : public Base {
public:
    A(int v) : p(v), Base(v) {}   // 派生类初始化列表中调用基类构造函数
private:
    int p;
};
```

补充：成员的**实际初始化顺序由类内声明顺序决定**，与初始化列表中的书写顺序无关。若两者不一致，`-Wreorder` 会告警，且可能出现"用未初始化成员去初始化另一个成员"的隐蔽 bug。

### 类的引用成员

引用成员有三条硬性约束：

1. 不能有默认构造函数（默认构造无法为引用提供初始化机制），必须提供构造函数；
2. 必须在成员初始化列表中完成初始化，写在函数体里是赋值，而引用不可赋值，编译报错；
3. 构造函数的形参**最好**是引用类型——注意这里是"最好"而不是"必须"：形参写成传值 `Ref(int target) : myref(target)` 也能编译，但 `target` 是函数局部对象，构造结束即销毁，`myref` 立刻变成悬垂引用，属于未定义行为。原文"形参必须是引用类型"应理解为"必须是引用，否则语义错误"。

```cpp
class Ref {
public:
    Ref(int &target) : myref(target) {      // 正确：形参是引用，成员在初始化列表绑定
        std::cout << "Ref constructor" << std::endl;
    }
    void printRef() { std::cout << "myref is: " << myref << std::endl; }
    virtual ~Ref() {}
private:
    int &myref;
};

int main() {
    int a = 20;
    Ref r(a);
    r.printRef();       // myref is: 20
    int &b = a;
    Ref r1(b);
    r1.printRef();      // myref is: 20
}
```

## 友元

友元函数是定义在类外、但被授予访问该类私有/保护成员权限的函数，用于在类之间共享数据时减少调用开销。

使用场景：运算符重载（如 `operator+` 需要左右操作数对称）、两个类需要互相访问内部数据。

- **优点**：提高效率（少一层成员函数调用）、写法自然；
- **缺点**：破坏封装，让类的内部表示暴露给外部函数。

使用要点：

1. 友元函数没有 `this` 指针，所以访问非 static 成员时必须显式传对象参数；只访问 static 成员或全局变量时不需要对象参数；参数是全局对象时也不需要；
2. 友元声明放在 private 段还是 public 段**没有区别**，因为它不是成员；
3. 可以直接像普通函数一样调用，不需要通过对象或指针；
4. 与成员函数的区别：没有 `this`；**友元关系不能被继承**（父亲的朋友未必是儿子的朋友），也不能传递。
5. 派生类的友元函数可以访问派生类从父类继承来的 protected 成员，但对父类而言它并不是友元。

## 命名空间

1. 可以嵌套；
2. 名字查找遵循**就近原则**（内层作用域隐藏外层同名名字）；
3. `namespace X { ... }` 结尾**没有分号**；
4. 匿名命名空间 `namespace { ... }` 中的名字具有内部链接，效果等价于 `static`，是现代 C++ 中替代"文件内 static 全局变量/函数"的推荐写法；
5. C++17 起支持嵌套命名空间的简写 `namespace a::b::c { ... }`。

## 有符号数的表示与右移

### 原码、反码、补码

- 首位是符号位（0 正 1 负），其余位表示数值；
- 正数的原码、反码、补码相同；
- 负数的反码：原码除符号位外按位取反；
- 负数的补码：反码 + 1；或者"原码自低位向高位，第一个 1 及其右边的 0 保持不变，左边各位按位取反，符号位不变"。

补码运算规则：

- `[x + y]补 = [x]补 + [y]补`
- `[x - y]补 = [x]补 + [-y]补`

以 `-3 - 4` 为例（4 位演示）：

```
[-3]补 = 1101
[-4]补 = 1100
相加   = 11001   → 舍去溢出位 → 1001 = -7
```

补码让减法可以用加法电路完成，这是它存在的根本原因。原码变补码、补码变原码都可以用"取反加一"：因为"取反前减 1"与"取反后加 1"效果相同（类似 `-3 - 1 = -(3 + 1)`）。

### 32 位 int 的关键数值

```
0000...0000  0
0111...1111  2147483647   最大的正整数
1000...0000  -2147483648  最小的负数
1111...1111  -1           最大的负数
```

最大正整数是 `0111...1111 = 2^31 - 1`；最小负数不是 `-2147483647`。原因在于 0 的原码有两种表示（`+0` 与 `-0`），而 0 只需要一个编码，于是把 `-0` 这个编码（`1000...0000`）用于表示 `-2^31`，使补码能比原码多表示一个负数。

### 有符号右移 `>>`

- 无符号数所有位都表示数值，没有原反补之分，右移高位一律补 0（逻辑右移）；
- 有符号数右移：正数高位补 0，负数补码高位补 1（算术右移）；
- **标准行为**：C++20 之前，负数的右移是 implementation-defined（实现定义），绝大多数编译器做算术右移；C++20 起标准明确规定有符号右移为算术右移（向负无穷取整）。写跨平台代码时若依赖负数右移，最好显式说明或改写成除法/位掩码形式。

正数示例 `4 >> 2`：

```
0000 0000 0000 0000 0000 0000 0000 0100
→ 0000 0000 0000 0000 0000 0000 0000 0001  = 1
```

负数示例 `-4 >> 2`：

```
原码 1000 ... 0100
补码 1111 ... 1100
右移 2 位（高位补 1）→ 1111 ... 1111
转回原码 → -1
```

所以 `-4 >> 2 == -1`，而不是 `-4 / 4 == -1` 之外的任何值；注意右移对负数是"向下取整"，而 `/` 是向零取整，两者在负数上不等价（`-5 >> 1 == -3`，而 `-5 / 2 == -2`）。

C++ 没有 `>>>` 运算符（那是 Java 的写法）；在 C++ 中要得到无符号右移，需先转换成无符号类型：

```cpp
int x = -4;
unsigned int ux = static_cast<unsigned int>(x);
int logical = static_cast<int>(ux >> 2);    // 高位补 0
```

## 整型溢出

`int` 的取值范围是 `[-2^31, 2^31-1]`。

```cpp
int a = -2147483648;    // INT_MIN
int b = a * -1;
int c = a - 1;
```

```cpp
// 常见输出
b = -2147483648
c = 2147483647
```

原因（以 32 位补码、二进制回绕的机器行为解释）：

- `c`：`-2147483648 - 1` 即 `0x80000000 + 0xFFFFFFFF = 0x17FFFFFFF`，截断到 32 位为 `0x7FFFFFFF = 2147483647`，回绕到最大正数；
- `b`：数学结果是 `2147483648`，超出 int 范围，机器码是 `0x80000000`，按补码解释正是 `-2147483648`。

**必须强调**：C++ 标准规定有符号整数溢出是**未定义行为（UB）**，上面的结果是典型的二补码回绕，但不是语言保证。开启 `-ftrapv` 或 UBSan（`-fsanitize=signed-integer-overflow`）可以捕获；`-fwrapv` 则让 GCC/Clang 明确按回绕处理。无符号整数的溢出是良定义的（模 2^N 回绕）。

另外，`int a = -2147483648;` 这个字面量本身也有讲究：`2147483648` 超出了 int，类型会变成 `long`/`long long`，一元负号作用后再转换回 int。严格写法是用 `<climits>` 里的 `INT_MIN` 或 `std::numeric_limits<int>::min()`。

## 求模与整数除法

- `%` 只能用于整数；浮点数求余用 `fmod`，或自行实现：

```cpp
float mod(float x, float y) {
    int tmp = (int)(x / y);
    return x - y * tmp;
}
```

- C++11 起，整数除法与取模都**向零截断**，余数的符号与被除数相同：`-7 / 2 == -3`，`-7 % 2 == -1`。C++11 之前除法/取模对负数的舍入方向是实现定义的。
- 浮点数与整数混合运算会提升为浮点：`7 / 2 == 3`，`7 / 2.0 == 3.5`。
- 向下/向上取整用 `floor`/`ceil`，注意它们与"向零取整"不同：

```cpp
floor(10.5) == 10;    floor(-10.5) == -11;   // 向负无穷
ceil(10.5)  == 11;    ceil(-10.5)  == -10;   // 向正无穷
```

- 常见陷阱：把"负数除以 2 会小于 0"当成循环终止条件。

```cpp
// 错误：步进用的是常量 child，循环变量 parent 从不改变，必然死循环
for (int parent = (child - 1) / 2; parent >= 0; parent = (child - 1) / 2) { /* ... */ }

// 正确：步进用 parent；终止条件写成 parent > 0，
// 否则 parent 降到 0 后 (0 - 1) / 2 仍为 0（向零截断），同样退不出来
for (int parent = (child - 1) / 2; parent > 0; parent = (parent - 1) / 2) { /* ... */ }

int a = -1;
int res = a / 2;    // 0，不是 -1
```

## 函数默认参数

C++ 允许为函数提供默认参数（缺省参数）。规则：

1. 有声明时，默认参数只能出现在声明或定义**其中之一**，不能两处都写；
2. 只有定义没有声明时，默认参数写在定义处；
3. 默认参数必须**从右向左**连续指定，不能出现"右边没有默认值、左边有"的情况；
4. 调用时传入的实参从左往右依次填入参数槽，剩余槽位使用默认值。

```cpp
void parameter_default(int a = 4, int b = 5, int c = 6) {
    std::cout << a << std::endl;
    std::cout << b << std::endl;
    std::cout << c << std::endl;
}

void parameter_default_multiply(int a, int b, int c = 4, int d = 5) {
    std::cout << a << b << c << d << std::endl;
}

parameter_default(8, 9);              // 8 9 6
parameter_default(7);                 // 7 5 6
parameter_default_multiply(1, 2, 3);  // 1 2 3 5
```

这条规则与"实参从左往右依次填入参数槽"一致，与参数入栈顺序没有因果关系（x64/AArch64 走寄存器传参，并不保证从右向左入栈）。栈帧（stack frame）中存放函数的参数、局部变量、需保存的寄存器值、返回地址以及结构化异常处理所需的数据；一次函数调用对应一个栈帧，进入函数时栈帧已完整建立（局部变量空间此时就分配好了），退出时整体销毁。

默认参数是**编译期**根据静态类型填入的，因此通过基类指针/引用调用时，默认值取的是基类声明的值，不会随动态类型变化——这与虚函数机制形成对照，是常见的混淆点。

## 语言层面的零散知识点

### 声明符中的 `*` 只作用于一个变量

```cpp
int *a, b;      // a 是 int*，b 是 int
int *a, *b;     // 两个都是 int*
```

`*` 是声明符的一部分而不是类型的一部分，所以一行里定义多个指针时每个变量前都要写 `*`。这也是"`int* a` 这种把 `*` 贴着类型的写法容易误导"的原因。

### 声明与定义

- 需要建立存储空间的叫定义：`int a;`；
- 不需要建立存储空间的叫声明：`extern int a;` 表示 a 在别的文件中定义，链接时再去找实现。

### 全局变量与 include

- C 语言不允许在两个源文件中定义同名全局变量：分别编译能过，链接时报重定义；
- 默认情况下全局变量和函数具有外部链接，跨文件访问需 `extern` 声明；加 `static` 则作用域局限在本 .cpp 内，相当于文件隔离；
- `#include` 的本质是文本复制；
- **头文件中的全局变量加 static**：多个源文件包含该头文件时会各自生成一份副本，各文件中的变量互不相同；不加 static 则所有源文件引用同一个变量，链接时报重定义。这也是"头文件里不要定义变量"（C++17 之前）的原因，需要共享时用 `extern` 声明 + 一处定义。

### 可以/不可以重载的情形

```cpp
class reload {
public:
    void fun(const char *p) {}   // 与下一个构成重载：底层 const 参与重载
    void fun(char *p) {}

    void fun1(char * const p) {} // 与下一个不能重载：顶层 const 被忽略
    void fun1(char *p) {}

    void fun2(int a) {}          // 与下一个不能重载：形参的顶层 const 无区别
    void fun2(const int a) {}
};
```

记忆：只有**底层 const**（指针/引用所指对象的 const）能区分重载；顶层 const（修饰形参本身）在函数签名中被忽略。

### if 条件的求值顺序

`||`、`&&` 以及 `if` 中的条件都从左向右求值，且具有短路语义。顺序写错会直接崩溃：

```cpp
// 错误：s2 为空时先调用 top() 是未定义行为
if (val <= s2.top() || s2.empty()) s2.push(val);

// 正确：先判空，短路后再取栈顶
if (s2.empty() || val <= s2.top()) s2.push(val);
```

### 自增表达式

```cpp
int b = 6;
int a = b++;    // a = 6, b = 7
```

后置 `++` 返回自增前的值（C++17 起 `i = i++ + 1;` 已良定义，但同一表达式中对同一变量多次修改仍属 UB，如 `i = i++ + i++;`）。

### 复合赋值运算符返回引用

```cpp
inline Vec3f& operator+=(const Vec3f& rhs) {
    _v[0] += rhs._v[0];
    _v[1] += rhs._v[1];
    _v[2] += rhs._v[2];
    return *this;
}
```

`+=`、`-=`、`*=`、`/=` 这类复合赋值应返回 `*this` 的引用，以支持链式调用并与内置类型语义一致；而 `+`、`-` 等二元运算符应返回值（新对象）。
