# 模板与泛型

> 导读：本篇把模板特化、奇异递归模板（CRTP）、`std::function` 与函数指针几条线索串起来。先看模板如何针对特定类型"特事特办"，再看 CRTP 如何用继承 + 模板在编译期实现静态多态和代码复用，最后回到运行期的可调用对象：普通函数指针、成员函数指针怎样声明与传递，`std::function` 又如何把它们统一成同一种类型。

## 一、模板的基本形态

```cpp
#include <iostream>

// 函数模板
template <typename T, class N>
void func(T num1, N num2)
{
    std::cout << "num1: " << num1 << ", num2: " << num2 << std::endl;
}

// 类模板
template <typename T, class N>
class TestClass
{
public:
    static bool comp(T num1, N num2) { return num1 < num2; }
};
```

在模板参数列表中，`typename` 与 `class` 完全等价。模板本身只是"代码生成方案"，编译器在看到具体类型（实例化）之前不会生成真正的函数/类。

### 1.1 为什么需要特化

泛型实现通常对所有类型走同一条路径。但某些类型需要完全不同的实现（例如 `bool` 的 `vector` 用位压缩、指针类型的 traits 要能取出 `value_type`），或者需要针对特定类型做优化。这时就要用**特化**给模板"开小灶"。

## 二、全特化

把主模板的所有模板参数都明确写死，就得到全特化版本。全特化后的类/函数已经不再是模板。

```cpp
// 主模板
template <typename T, class N>
void func(T num1, N num2)
{
    std::cout << "primary" << std::endl;
}

// 全特化：两个参数都被明确化，template<> 中是空的
template <>
void func(int num1, double num2)
{
    std::cout << "full specialization: " << num1 << ", " << num2 << std::endl;
}

template <typename T, class N>
class TestClass
{
public:
    static bool comp(T num1, N num2) { return num1 < num2; }
};

// 类模板的全特化
template <>
class TestClass<int, double>
{
public:
    static bool comp(int num1, double num2) { return num1 < num2; }
};
```

调用：

```cpp
func<int, double>(1, 2.0);              // 命中全特化版本
TestClass<int, double>::comp(1, 2.0);   // 命中全特化类
```

全特化的两个条件：

1. 必须存在一个主模板；
2. 模板参数被**全部**明确化。

函数模板和类模板都允许全特化。

## 三、偏特化

### 3.1 类模板偏特化

偏特化介于主模板与全特化之间：模板名与主模板相同，但只有**一部分**模板参数被明确化。

> 重要：C++ 只允许**类模板**（以及 C++14 起的变量模板）偏特化，**函数模板不能偏特化**。

```cpp
template <typename T, class N>
class TestClass
{
public:
    static bool comp(T num1, N num2) { return num1 < num2; }
};

// 偏特化：第一个参数固定为 int，第二个仍由模板参数 N 决定
template <class N>
class TestClass<int, N>
{
public:
    static bool comp(int num1, N num2) { return num1 < num2; }
};
```

调用 `TestClass<int, double>::comp(1, 2.0)` 会命中上面的偏特化版本。

### 3.2 函数模板的"偏特化"其实是重载

原始笔记给出过下面这段代码，并称之为"模板函数偏特化"：

```cpp
// 注意：这不是偏特化，而是一个新的函数模板重载
template <class N>
void func(int num1, N num2)
{
    std::cout << "num1: " << num1 << ", num2: " << num2 << std::endl;
}
```

这段代码本身合法，但它的身份是**重载**，不是偏特化。由此带来两个容易踩坑的细节：

- 对 `func(1, 2.0)` 这样的调用，重载决议会优先选择更特化的 `func(int, N)`，效果看起来像偏特化；
- 但如果写成 `func<int, double>(1, 2.0)`，显式给出了两个模板实参，而重载版本只有一个模板参数 `N`，它就不再是候选，最终会落到 `func(int, double)` 的全特化上（若不存在该全特化，才回到主模板）。

所以，函数模板想对部分参数做特化时，正确做法是**提供重载**，而不是试图写偏特化语法。

### 3.3 调用优先级

主模板、偏特化、全特化同时存在时，优先级从高到低为：

**全特化 > 偏特化 > 主模板**

### 3.4 典型应用：iterator_traits

偏特化不只是性能优化手段，更常见的作用是"让泛型代码对更多类型成立"。STL 的 `iterator_traits` 就是标准案例：

```cpp
template <class Iterator>
struct iterator_traits
{
    typedef typename Iterator::value_type        value_type;
    typedef typename Iterator::difference_type   difference_type;
    typedef typename Iterator::pointer           pointer;
    typedef typename Iterator::reference         reference;
    typedef typename Iterator::iterator_category iterator_category;
};

// 偏特化：裸指针
template <class T>
struct iterator_traits<T*>
{
    typedef T                          value_type;
    typedef ptrdiff_t                  difference_type;
    typedef T*                         pointer;
    typedef T&                         reference;
    typedef std::random_access_iterator_tag iterator_category;
};

// 偏特化：指向 const 的裸指针
template <class T>
struct iterator_traits<const T*>
{
    typedef T                          value_type;
    typedef ptrdiff_t                  difference_type;
    typedef const T*                   pointer;
    typedef const T&                   reference;
    typedef std::random_access_iterator_tag iterator_category;
};
```

算法只依赖 `iterator_traits<It>::value_type` 这类嵌套类型。迭代器类自己定义了这些 typedef，而裸指针没有，于是用两个偏特化把指针"伪装"成迭代器。这样 `std::sort(arr, arr + n)` 才能直接作用于 C 风格数组，而不必为指针重载每一个算法。

## 四、奇异递归模板（CRTP）

CRTP（Curiously Recurring Template Pattern）的写法是：**把派生类自身作为基类的模板参数**。

```cpp
template <typename Derived>
class Base
{
    // ...
};

class Derived : public Base<Derived>
{
    // ...
};
```

它的主要用途有两个：静态多态、精简重复代码。

### 4.1 静态多态

```cpp
#include <iostream>

template <typename Child>
struct Base
{
    void interface()
    {
        // 编译期完成向下转换，无虚函数、无 vtable
        static_cast<Child*>(this)->implementation();
    }
};

struct Derived : public Base<Derived>
{
    void implementation()
    {
        std::cerr << "Derived implementation\n";
    }
};

int main()
{
    Derived d;
    d.interface();   // 输出 Derived implementation
}
```

调用链在编译期就确定了：`Base<Derived>::interface()` 里的 `static_cast<Child*>(this)` 得到 `Derived*`，直接调用 `Derived::implementation()`，不需要虚表间接寻址，也就没有虚调用开销，且更容易被内联。

第二个例子把"基类算法 + 子类实现"抽象出来：

```cpp
template <typename Child>
class Animal
{
public:
    void run() { static_cast<Child*>(this)->runImpl(); }
};

class Dog : public Animal<Dog>
{
public:
    void runImpl() { std::cout << "Dog run" << std::endl; }
};

class Cat : public Animal<Cat>
{
public:
    void runImpl() { std::cout << "Cat run" << std::endl; }
};

template <typename T>
void Action(Animal<T>& animal)
{
    animal.run();
}

int main()
{
    Dog dog;
    Action(dog);
    Cat cat;
    Action(cat);
}
```

> 原始笔记中子类的实现函数也叫 `run`，与基类的 `run` 同名。这样写虽然能编译（派生类同名函数会隐藏基类版本），但可读性差，而且一旦子类忘记实现，`static_cast<Child*>(this)->run()` 会解析回基类的 `run`，造成无限递归。上面的改写用 `runImpl` 明确区分了"接口"和"实现"。

### 4.2 精简代码：向量运算符复用

`Vector2/3/4` 都需要 `+=`、`-=` 等运算符，且这些运算符都可以由 `+`、`-` 推导出来。用 CRTP 把公共部分提到基类：

```cpp
template <typename T>
struct VectorBase
{
    T&       underlying()       { return static_cast<T&>(*this); }
    const T& underlying() const { return static_cast<const T&>(*this); }

    T& operator+=(const T& rhs)
    {
        underlying() = underlying() + rhs;
        return underlying();
    }

    T& operator-=(const T& rhs)
    {
        underlying() = underlying() - rhs;
        return underlying();
    }
};

struct Vector3 : public VectorBase<Vector3>
{
    float x = 0.0f, y = 0.0f, z = 0.0f;

    Vector3() = default;
    Vector3(float _x, float _y, float _z) : x(_x), y(_y), z(_z) {}

    // 二元运算符应写成友元/自由函数：成员形式的 operator+ 只能接受一个显式参数
    friend Vector3 operator+(const Vector3& lhs, const Vector3& rhs)
    {
        return Vector3(lhs.x + rhs.x, lhs.y + rhs.y, lhs.z + rhs.z);
    }

    friend Vector3 operator-(const Vector3& lhs, const Vector3& rhs)
    {
        return Vector3(lhs.x - rhs.x, lhs.y - rhs.y, lhs.z - rhs.z);
    }
};

int main()
{
    Vector3 v0(6.0f, 5.0f, 4.0f);
    Vector3 v2(4.0f, 5.0f, 6.0f);
    v0 += v2;
    v0 -= v2;
}
```

> 原始笔记把 `operator+` 写成成员函数 `Vector3 operator+(const Vector3& lhs, const Vector3& rhs)`，参数多了一个，无法通过编译；同时 `Vector3 result;` 又调用了不存在的默认构造函数。上面已一并修正。

### 4.3 使用 CRTP 的注意事项

- **编译期绑定**：`Base<Derived>` 与 `Base<Other>` 是不同类型，不能放进同一个 `Base*` 容器，因此它替代不了运行时多态。
- **基类析构函数不是虚函数**：不要通过基类指针 `delete` 派生类对象。
- **代码膨胀**：每个派生类都会实例化一份基类模板，派生类多时二进制体积会增长。
- **编译期耦合**：派生类必须在基类成员被实例化之前是完整类型，头文件依赖较强。
- C++23 的"显式对象参数"（deducing this）可以更优雅地实现同类效果，可视为 CRTP 的现代替代方案。

## 五、`std::function`：统一所有可调用对象

C++ 中的可调用对象至少有四类：

| 类别 | 示例 |
|:---|:---|
| 函数 / 函数指针 | `bool f(int, int)`、`&f` |
| lambda 表达式 | `[](int a, int b) { return a > b; }` |
| 仿函数（重载了 `operator()` 的类） | `compare_class()` |
| `std::bind` 产生的对象 | `std::bind(...)` |

它们的类型各不相同，`std::function<Signature>` 用类型擦除把它们统一成同一种可拷贝、可赋值的类型。

```cpp
#include <iostream>
#include <functional>

std::function<bool(int, int)> fun;   // 接受两个 int、返回 bool

bool compare_com(int a, int b) { return a > b; }

auto compare_lambda = [](int a, int b) { return a > b; };

class compare_class
{
public:
    bool operator()(int a, int b) { return a > b; }
};

class compare
{
public:
    bool compare_member(int a, int b) { return a > b; }
    static bool compare_static_member(int a, int b) { return a > b; }
};

int main()
{
    fun = compare_com;
    std::cout << fun(1, 2) << std::endl;          // 0

    fun = compare_lambda;
    std::cout << fun(2, 1) << std::endl;          // 1

    fun = compare_class();
    std::cout << fun(3, 1) << std::endl;          // 1

    fun = compare::compare_static_member;         // 静态成员函数等价于普通函数
    std::cout << fun(1, 3) << std::endl;          // 0

    // 非静态成员函数：必须绑定对象，并写 &类名::函数名
    compare temp;
    fun = std::bind(&compare::compare_member, temp,
                    std::placeholders::_1, std::placeholders::_2);
    std::cout << fun(1, 2) << std::endl;          // 0
}
```

### 5.1 成员函数的三种绑定方式

```cpp
compare temp;

// 1) std::bind
std::function<bool(int,int)> f1 =
    std::bind(&compare::compare_member, temp, std::placeholders::_1, std::placeholders::_2);

// 2) lambda（通常更清晰，也更容易被内联）
std::function<bool(int,int)> f2 =
    [&temp](int a, int b) { return temp.compare_member(a, b); };

// 3) std::mem_fn（C++11）：它得到的是 bool(compare&, int, int) 这类可调用对象，
//    必须再 bind 上对象实参，不能直接赋给 std::function<bool(int,int)>
auto mf = std::mem_fn(&compare::compare_member);
std::function<bool(int,int)> f3 =
    std::bind(mf, temp, std::placeholders::_1, std::placeholders::_2);
```

注意 `std::bind` 默认**按值拷贝**绑定的对象；需要引用语义时用 `std::ref(temp)`。

### 5.2 开销与取舍

- `std::function` 使用类型擦除，调用通常是一次间接调用，难以内联；
- 当可调用对象较大时可能发生堆分配（小对象优化因实现而异）；
- 它要求可调用对象**可拷贝**（C++23 的 `std::move_only_function` 放宽了这一限制）；
- 热路径上优先用模板参数、函数指针或 `auto` 接收 lambda；需要存储/回调注册时再用 `std::function`。

## 六、函数指针

### 6.1 声明、赋值与调用

```c
int Func(int x);        /* 声明一个函数 */
int (*p)(int x);        /* 定义一个函数指针 */
p = Func;               /* 函数名退化为函数地址 */
int y = (*p)(1);        /* 通过函数指针调用 */
int z = p(1);           /* 等价写法，括号里的 * 可省略 */
```

`(*p)(1)` 与 `p(1)` 完全等价。函数名在大多数表达式中会退化为指向该函数的指针。

### 6.2 `typedef` / `using` 简化

```cpp
typedef int (*FP_CALC)(int, int);   // FP_CALC 是“函数指针类型”
FP_CALC fp = add;

// C++11 起更推荐
using FP_CALC2 = int (*)(int, int);
```

### 6.3 返回函数指针的函数

```cpp
typedef int (*FP_CALC)(int, int);

FP_CALC calc_func(char op);          // 返回函数指针（借助 typedef）

// 不借助 typedef 的等价写法：把函数名换成 (*name(args))
int (*s_calc_func(char op))(int, int);
```

一个完整的四则运算例子：

```cpp
#include <cassert>

typedef int (*FP_CALC)(int, int);

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
int mul(int a, int b) { return a * b; }
int divi(int a, int b) { return b ? a / b : -1; }

FP_CALC calc_func(char op)
{
    switch (op)
    {
    case '+': return add;
    case '-': return sub;
    case '*': return mul;
    case '/': return divi;
    default:  return nullptr;
    }
}

int (*s_calc_func(char op))(int, int)
{
    return calc_func(op);
}

int calc(int a, int b, char op)
{
    FP_CALC fp = calc_func(op);
    assert(fp == s_calc_func(op));
    return fp ? fp(a, b) : -1;
}
```

> 原始笔记中"`typedef int func(int, int); func x = add;`"的写法有误：`func` 是**函数类型**，`func x;` 声明的是一个函数，不能用另一个函数去初始化。正确写法是 `func* x = add;` 或 `typedef int (*func)(int, int);`。同理，"去掉星号和括号"得到的只是函数类型别名，之后仍需显式加 `*` 才能声明指针。

### 6.4 成员函数指针

普通函数指针存的是代码地址；成员函数指针存的是**函数地址（虚函数则为虚表槽位索引）加上 this 调整量**。因此成员函数指针必须与一个具体对象（或对象指针）结合才能调用。

```cpp
class A
{
public:
    int i1 = 0;
    int fun1(int i) { return i; }
};

int (A::*fp)(int) = &A::fun1;   // 成员函数指针，必须写 &
int A::*ip = &A::i1;            // 成员变量指针

A oba;
(oba.*fp)(1);       // 通过对象调用
(oba.*ip) = 2;      // 通过对象访问成员

A* poba = &oba;
(poba->*fp)(1);     // 通过对象指针调用
```

要点：

- 取成员函数地址必须用 `&A::fun1`，写成 `oba.fun1` 不合法；
- 调用必须用 `.*`（对象）或 `->*`（对象指针）；
- 静态成员函数没有 `this`，其指针就是普通函数指针，可直接赋值给 `int (*)(int)`。

### 6.5 把成员函数指针作为参数传递

```cpp
class A
{
public:
    int fun1(int i) { return i; }
};

// 版本一：绑定具体类型 A
void fun2(int j, A* obp, int (A::*p)(int))
{
    std::cout << (obp->*p)(j);
}

// 版本二：泛化到任意类型 T
template <class T>
void fun2(int j, T* obp, int (T::*p)(int))
{
    std::cout << (obp->*p)(j);
}

// 版本三：同时支持普通函数指针（重载）
void fun2(int j, int (*p)(int))
{
    std::cout << p(j);
}

int fun3(int i) { return i; }

int main()
{
    int (A::*fp1)(int) = &A::fun1;
    A oba;
    fun2(1, &oba, fp1);   // 成员函数
    fun2(1, fun3);        // 普通函数
}
```

关键点：

1. **必须额外传入对象或对象指针**——只有函数地址（或槽位索引）与 this 调整量，无法定位到实际内存；
2. 模板版本中，参数类型必须写成 `int (T::*p)(int)`，写成 `int (A::*p)(int)` 就丢失了泛型性；
3. 对象参数建议用指针而非值传递，避免拷贝，也便于统一处理。

> 原始笔记里"通用函数"的第一个版本写成了 `template <class T> void fun2(int, T* obp, int (A::*p)(int))`，模板参数 `T` 与成员指针的类类型 `A` 不一致，无法匹配任意类；应改为 `int (T::*p)(int)`。

### 6.6 现代替代方案

- `std::function`：类型擦除，适合回调注册；
- lambda：可直接捕获对象，最易读，也最容易被内联；
- `std::mem_fn` / `std::invoke`（C++17）：统一处理成员函数指针与普通可调用对象；
- 模板参数：把可调用对象类型作为模板参数，零开销，适合算法/策略。
